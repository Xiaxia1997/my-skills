# 论文中文精读

把一篇英文论文变成能直接读的中文长文,落进用户的笔记目录(默认按 Obsidian vault 的格式要求)。

**核心原则:忠实优先于流畅。** 用户要的是"读中文等于读原文",不是二次创作。宁可句子笨一点,也不能改变原意、抹掉作者的不确定语气、或把推测写成结论。

---

## 一、先决条件

- Python 3,依赖 `lxml`;抽图需要 poppler 命令行工具(`pdftotext` / `pdftoppm` / `pdfinfo`,macOS 可 `brew install poppler`)。缺依赖先告诉用户,不要擅自装包
- 落盘位置:`<笔记目录>/YYYY-MM-DD-<论文名>精读.md`
  - `<笔记目录>` 先从项目 CLAUDE.md / AGENTS.md 或 memory 里找;找不到就问用户,别猜
  - 平铺单文件,**不建子目录**
  - 日期用今天
- 若笔记目录是 git 仓库,收尾时询问用户是否 commit + push

## 二、流程

### 步骤 1:拿到原文

**优先要 arXiv HTML,不要 PDF。** HTML 版由 LaTeXML 生成,公式带 `alttext` 属性可无损还原成 LaTeX,章节结构干净;PDF 双栏排版提取出来公式和表格会错乱。

```bash
curl -sL -A "Mozilla/5.0" "https://arxiv.org/html/<ID>v1" -o /tmp/paper.html
```

若用户只给了论文名,先 WebSearch 找 arXiv 编号,**把找到的编号和标题报给用户确认**再开工——搞错论文比慢一点糟糕得多。

若确实只有 PDF,用 Read 工具分批读(每次 ≤20 页),但要在成稿里注明"由 PDF 提取,公式可能有损"。

### 步骤 2:提取结构

```bash
python3 scripts/extract.py /tmp/paper.html /tmp/blocks.json
```

会打印块数、正文词数和章节清单。**先看这份清单再决定怎么分批**——按章节切,每批 ≤ 约 5000 词,太大质量会掉。

### 步骤 3:抽插图

**论文的架构图往往比正文更有信息量,不能漏。** 图有两个来源,要都跑:

```bash
# 来源一:arXiv HTML 里的 <img>(照片、外部图片,原始分辨率最高)
python3 scripts/figures.py html /tmp/paper.html <arxiv_id> /tmp/figs

# 来源二:从 PDF 裁(TikZ 等矢量图 LaTeXML 渲染不出来,HTML 里是空的)
python3 scripts/figures.py pdf /tmp/paper.pdf /tmp/figs
```

⚠️ **只跑 HTML 那一路会丢掉大部分架构图。** 以 DeepSeek-V4 为例:31 个 `<figure>` 里只有 5 个有真图,
Figure 2–6(整体架构、CSA、HCA、EP 方案、KV cache layout)在 HTML 里全是空的,必须从 PDF 裁。
没有 PDF 就去 arXiv 下:`curl -sL https://arxiv.org/pdf/<ID> -o /tmp/paper.pdf`

**产出必须目视检查**,别只看跑通了没有:

- 文件只有 1–3KB → 多半裁空了或只裁到一条文字
- 用 Read 工具打开抽查 2–3 张,确认图完整、没把正文切进来

`figures.py` 的裁剪靠三条判据:图注必须在行首、上方要有足够留白(排除「Figure 10 presents…」这类正文句)、
正文行既宽又贴左边距(排除图内那些横跨整幅但缩进的元素)。版式特殊的论文可能失手,所以目视检查是必须的。

**落盘与插入**:图片放 `<笔记目录>/assets/<论文简称>/`,正文用相对路径引用,
插在**首次提到该图的段落之后**,并在下方补一行斜体图注:

```markdown
![Figure 2:整体架构](assets/deepseek-v4/figure2.png)

*Figure 2:整体架构*
```

### 步骤 4:逐章翻译

按章节读 `blocks.json` 的原文,逐章写成中间稿(临时文件放 scratchpad,不要写进笔记目录)。

翻译规则见下方第三节,**这是本 skill 的核心,不能省**。

### 步骤 5:合成 + 清理 + 校验

```bash
python3 scripts/finalize.py <中间稿目录> <输出.md> --title "<中文标题>" --meta "<元信息行>"
```

`finalize.py` 依次做四件事:
1. 合并各章,统一标题层级(章 `##` / 节 `###` / 小节 `####`)
2. 删除参考文献编号(保留枚举序号、公式数字、年份)
3. 校验格式合规(见第四节)
4. 报告统计

脚注需要手工插入(只有你知道哪里有歧义),见第三节第 4 条。

### 步骤 6:落盘并提交

```bash
cd <笔记目录所在仓库> && git add "<文件相对路径>" && git commit -m "learning: <论文名>中文精读" && git push
```

⚠️ **只 `git add` 自己的文件**。该仓库常有用户未提交的改动,不要 `git add -A`。

## 三、翻译规则(核心)

### 1. 术语一律保留英文原形

MoE、KV cache、top-k、attention sink、residual stream、test-time scaling……正文里**不要**替换成中文。

首次出现可以括注中文释义(如 `non-expansive(非扩张的)`),之后直接用英文。

**不要在文首放术语表**——用户明确说过阅读时不需要,那是干扰。

### 2. 参考文献引用直接不译入

论文的引用有两种格式:数字编号 `(63; 25)` 和作者-年份 `(Wang et al. 2024)`。
**翻译时一律略去,不要写进译文**——正文没有参考文献列表,写了也点不开,只会打断中文语感。

`finalize.py` 只能兜底清理数字编号那种;作者-年份格式它不碰(容易误伤正常括号),
所以必须在翻译阶段就不写。

### 3. 照抄不译的东西

公式、变量名、benchmark 名、数字指标、超参数值、模型名、算法名、代码标识符,一律原样保留。数字**逐个核对**,不做任何"顺手改写"。

### 4. 保留作者的限定语气(最容易出错的地方)

| 原文 | 必须译成 | 绝不能译成 |
|---|---|---|
| may / might | 可能 | 会 |
| suggests / indicating | 表明 | 证明 |
| we hypothesize | 我们推测 | 我们发现 |
| we observe / we find | 我们观察到 / 我们发现 | 已证实 |
| appears to | 似乎 | 就是 |
| theoretically | 理论上 | 实际上 |
| approximately / roughly | 大约 | 精确的数字 |
| marginally | 略微 | 显著 |

LLM 翻译最常见的失真就是把 hedge 抹平成断言。**每遇到一个限定语,停下来确认译文保住了那份不确定。**

### 5. 歧义处挂脚注,附英文原文

用 Markdown 脚注 `[^n]`,定义集中放文末:

```markdown
理论上在未来硬件上可以实现高出 1/3 的效率[^1]

[^1]: 原文:they can theoretically be implemented to be 1/3 more efficient on future hardware
```

**什么该挂脚注**(挑真会影响判断的,一篇 15~20 条为宜,不要滥用):
- 作者用了 hedge、结论其实没那么硬的地方
- 含糊的指标(如 `non-loss rate` 不是胜率)
- 有前提条件的结论(如"经验验证"而非理论保证)
- 推理链绕、中文难以完全承载的论证
- 一个词有两种合理理解、你必须选一种的地方

### 6. 不做中英文对照

正文只有中文。英文只出现在脚注和保留的术语里。

### 7. 每章末加「小结(译者归纳,非原文)」

3~6 条,提炼这一章真正重要的东西。必须**明确标注是译者归纳**,与原文严格区分。

用 ⚠️ 标记这几类:
- 结论有前提、有例外
- 与原文行文重点不一致(比如原文强调赢了 A,但表里 B 更强)
- 作者自己承认的短板

这是精读稿比机翻值钱的地方,但也是最容易过度推断的地方——**只写原文支持的东西**。

### 8. 不留空的笔记占位符

不要写孤零零的 `📝`。带内容的译者提示可以留,格式:

```markdown
📝 *(译者提示:……)*
```

## 四、Obsidian 格式硬规则

面向 Obsidian vault;**违反会导致 Obsidian 渲染出错**。若用户的笔记目录有自己的格式约定(见其 CLAUDE.md / AGENTS.md),以用户约定为准:

- **禁用行内 `$...$`**。行内数学写成反引号包裹的 Unicode:`` `n_hc` ``、`` `ℝ^(n×d)` ``、`` `‖B_l‖₂` ``、`` `m′` ``、`` `α_l` ``
- 独立公式用 `$$`,`$$` 必须**独占一行**、前后留空行,中间保持原文 LaTeX
- 文件名 `YYYY-MM-DD-中文名.md`,正文直接 `# 标题` 开头,不加 frontmatter

常用符号对照:`ℝ ⊙ ≫ × ∈ ∑ ‖ ⁻¹ ₂ 𝓜 𝓕 α β γ θ π σ Δ ′`

`finalize.py` 会自动校验这几条,不合规会报错。

## 五、成稿结构

```
# <中文标题>

> 原文:<English Title>
> arXiv:<链接> · <权重/代码链接(如有)>
> 作者:<机构>(N 位署名)· <发布时间>

---

## Abstract 摘要
## 1 Introduction 引言
### 1.1 ...
### 小结(译者归纳,非原文)

## 第 2 章 <English Title> <中文>
...

---

## 脚注:歧义处的英文原文

[^1]: 原文:...
```

开头**直接进正文**,不要放阅读说明、术语表、目录。

## 六、常见坑

| 坑 | 后果 | 对策 |
|---|---|---|
| 用 PDF 而非 HTML 提正文 | 公式表格错乱 | 正文用 arXiv HTML,插图另从 PDF 裁 |
| 只从 HTML 抓图 | 架构图全丢(LaTeXML 渲染不出 TikZ)| 两个来源都跑,见步骤 3 |
| 抽完图不看 | 裁空/裁歪了也不知道 | 用 Read 目视抽查,留意 1–3KB 的小文件 |
| 一次翻整篇 | 后半段质量断崖 | 按章切,每批 ≤5000 词 |
| 抹平 hedge | 把推测写成结论,误导用户 | 见第三节第 4 条 |
| 用行内 `$...$` | Obsidian 不渲染 | 用 Unicode + 反引号 |
| 删引用编号时误删枚举 | `(1)(2)(3)` 小标题被吃掉 | 用 `finalize.py`,它已处理 |
| 章节符号不给值 | 读者不知道 `m` 到底是几 | 超参常在「训练设置」章,回头补一张速查表并交叉引用 |
| `git add -A` | 提交用户未完成的改动 | 只 add 自己的文件 |

## 七、收尾

告诉用户:文件路径、总行数、脚注条数、以及**原文里值得注意的 2~3 个点**(尤其是作者自己承认的短板、与宣传口径不一致的数字)。这比复述"翻完了"有用得多。
